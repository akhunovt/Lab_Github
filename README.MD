# Лабораторная работа № 2, вариант 6

Тема: проектирование и реализация двух моделей данных для учебного графика дисциплин факультета. СУБД: PostgreSQL.

## Цель работы

Реализовать две модели данных для одной предметной области («учебный график факультета»):

Нормализованная модель в 3‑й нормальной форме (3NF) — для оперативной работы и простых запросов. Модель по методологии Data Vault 2.0 — для хранения истории изменений и интеграции данных.

## Структура репозитория

В репозитории находится SQL‑скрипт, который:

удаляет старые схемы (если есть) и создаёт две независимые схемы: `university_3nf` и `university_dv`; формирует таблицы, ограничения, индексы и комментарии к объектам.

## Модель 3NF (university_3nf)

Упрощённая реляционная модель для типичных задач учёта:

Таблицы: `study_group`, `discipline`, `teacher`, `curriculum`, `curriculum_discipline`.

Особенности: первичные и внешние ключи; CHECK-ограничения (учебный год, номера семестров, типы контроля и т. д.); уникальные ограничения (например, комбинация группы, учебного года и версии); индексы для ускорения выборки по группе и преподавателю; комментарии к таблицам для документирования назначения. Подходит для повседневных операций: расписания, отчётов по нагрузке, форм контроля.

## Модель Data Vault (university_dv)

Реализация по принципам Data Vault 2.0:

4 хаба (HUB): `hub_group`, `hub_discipline`, `hub_teacher`, `hub_curriculum` — хранят бизнес‑ключи и метаданные загрузки.

2 линка (LINK): `link_curriculum_group`, `link_curriculum_discipline_teacher` — фиксируют связи между сущностями.

5 сателлитов (SATELLITE): хранят описательные атрибуты и поддерживают версионность (история изменений) через поле `load_dts` и `hashdiff`. Индексы на сателлитах для быстрого получения актуальных версий записей. Такая структура позволяет сохранять историю изменений (например, смена преподавателя по дисциплине или корректировка часов) без потери старых данных.

## Как запустить

Установите и запустите PostgreSQL. Создайте базу данных (например, `university_lab`). Выполните скрипт в клиенте (psql, DBeaver, pgAdmin и др.) в контексте этой БД. Проверьте наличие схем `university_3nf` и `university_dv` и созданных таблиц.

Пример команды в psql:

```bash
psql -h localhost -U postgres -d university_lab -f lab2_variant6.sql
```
